## The problem

Many companies run a business rule that nobody can read any more. It lives in an Excel workbook: a discount threshold in one cell, a delivery rule in another, a macro that rounds the points. The person who wrote it has left. When someone rewrites it in code, nobody can say whether the rewrite agrees with the workbook, and sometimes the workbook disagrees with itself.

## Who has it

People who own one such workbook, in finance, sales operations, logistics or engineering, and who are not a large enterprise with a VBA portfolio to migrate. [OWNER: who you had in mind, and any real person or case you want to name.]

## Who can use this after the hackathon
- Anyone with Python 3.11 and LibreOffice can run Ghost on one of their own workbooks from a clone: the README section "Use it on your own workbook" lists the four commands and what is not supported.
- The proof report is a file (HTML and JSON), so it can be attached to a review or a ticket. It states what was not checked.
- `ghost challenge` takes any rewrite, human or AI, and runs it against the workbook; the line-up in `samples/suspects/MEASURED.md` shows what it finds.
- `CONTRIBUTING.md` explains how to run the tests, add a sample workbook, add a suspect and keep the honesty rule. Nothing has been used by anyone outside this project yet.

## What Ghost does

Ghost takes one workbook (formulas first, VBA read statically and never run) and produces three things (README, "What it does"):

1. Plain-English rules in EARS form, each traced to the cell it came from.
2. A pure-function Python module, `compute(inputs) -> outputs`, and a small web app around it.
3. A proof report. The new module is run against the original workbook recalculated by headless LibreOffice (the "Referee"), with property-based tests and a fixed seed (20261204). A pass reads "no difference found on N cases"; it never says "correct".

The demo that shows what is different: the bundled "haunted discount calculator" gives free delivery above 50 units but the discount from 50 units. Ghost's autopsy raises Finding F-001 on that. In Faithful mode the module reproduces the workbook, quirk included, and passes. After the person records Decision D-001, "bulk means 50 or more", Intended mode shows exactly one expected difference: at quantity 50 the workbook says 6.0 and the new code says 0 (`docs/img/verdict-card.png`, made from a real run). A mutation self-check plants bugs in the module and reports how many the verifier catches (31 of 33 on the discount sample, 33 of 35 on the haunted one, `docs/KIRO_USAGE.md`).

## What is different from existing tools

- AWS Transform custom migrates VBA code across portfolios. Its documentation says nothing about worksheet formulas or workbook size (`docs/AWS_TRANSFORM_FACTS.md`). Ghost takes one workbook, formulas included, and checks the result against the original workbook as the referee. Large VBA is routed to AWS Transform custom: `ghost handoff` writes the kit and `ghost challenge` / `ghost receipt` referee what comes back. Nothing here has been run against AWS.
- A mismatch is not always a bug in the new code. The workbook can be the one that is wrong, so a person decides and the decision is recorded (`decisions.yaml`).
- Trial by Workbook: `ghost challenge` lets the workbook referee anyone's rewrite, including code an AI agent wrote. In the repository an agent migration was corrected by the loop (`.kiro/specs/haunted-delivery-migration/README.md`); that round was not blind and one round's input domains were confirmed by the Owner afterwards (same README).

## Challenges

- LibreOffice is not Excel. The Referee is LibreOffice, so a pass means a match with LibreOffice; seven known differences are listed in the README. Nothing is checked in Excel.
- Honest wording is enforced, not hoped for: the verdict card, the README and the kit avoid "correct" and "proven", and tests check that.
- A workbook that disagrees with itself needs a human, not a coin flip.
