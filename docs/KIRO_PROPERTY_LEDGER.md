A row is bound first by an explicit comment in a test file, `Feature: <spec>, Property N`; only if there is none, a test file that names the number and also names that spec (or is listed in that spec's tasks, design or requirements) covers it. In this table covered means a test names the property; it may be an example test, not a Hypothesis one. "ambiguous" means a test file names the number but nothing ties it to this spec. "caught" holds a bug only where `docs/KIRO_USAGE.md` says the property caught it; otherwise "none recorded". A covered row means a test cites the property; it does not mean the test is strong.
