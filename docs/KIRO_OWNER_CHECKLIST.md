# Kiro owner checklist

Steps only the repository Owner can do, because they need the Kiro IDE. The Result column is empty on purpose. The Build_Agent does not fill it in on its own; it only records a Result the Owner dictates, marked as such.

## How to fill this in

Do each row in Kiro, compare what you see with "What to expect", and write in the Result cell the date, `pass` or `fail`, and what you saw (for example, the text of the hook output, or the error message). Leave the cell empty for a row you did not try. Record a `pass` only for something you observed in Kiro. A file that exists, or a test that passes outside Kiro, is not a pass.

README and the write-up may say a surface "works in Kiro" only for a row whose Result cell holds an observed pass (Requirement 9). For every other row they must say "not checked in Kiro".
